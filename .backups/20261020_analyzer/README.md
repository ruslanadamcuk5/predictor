# Betcity Predictor — Android

Мобильное приложение, которое **само** запускает движок прогнозов из `17allsets.py`.
Python-ядро встроено в APK через Chaquopy и работает на телефоне — сервер не нужен.

Готовый файл: `Predictor-1.3.apk` (рядом с папкой проекта).

---

## Установка

1. Скопируйте `Predictor-1.3.apk` на телефон (кабель, облако, Telegram «Избранное»).
2. Откройте файл на телефоне.
3. Разрешите установку из неизвестных источников, если система спросит.
4. При первом запуске разрешите уведомления (для сигналов в штрафной строке).

Требования: Android 7.0+ (API 24), 64-битный процессор (arm64-v8a).
Приложение не из Google Play, поэтому Play Protect может показать предупреждение —
это нормально для самодельных APK.

Через ADB:

```powershell
C:\Android\platform-tools\adb.exe install -r Predictor-1.3.apk
```

## Экраны

### Панель
Состояние движка, кнопки **Запустить / Остановить / Проверить**, счётчики
(проверено, сигналов, пропущено, отсечено), hit rate, последние события и
техническая сводка.

### Очередь
Живая линия Betcity: команды, счёт, коэффициенты, лига. Фильтры «Все / Скоро /
Отправлены / Обработаны». Кнопка «Обновить» перезапрашивает линию.
У матчей, на которые уже дан сигнал, прямо в карточке виден сам прогноз:
партия, ставка и результат по ней («зашла · 11:7» / «не зашла · 9:11»).

### Результаты
История всех игр с прогнозами. Для каждой игры показаны:
- команды, лига, время сигнала и дата матча, итоговый счёт;
- каждый прогноз (партия и вид ставки), вердикт и статус;
- **обоснование** — какие модели и с какой уверенностью голосовали
  (строка «Модели: …»), уверенность, число согласных моделей, согласие,
  порог тотала;
- результат по партии: счёт, тотал, «зашла / не зашла / ожидает».

Фильтр: дата и время «с» и «по», быстрые диапазоны (Сегодня / 7 дней / 30 дней /
Всё время), поиск по команде или лиге, статус (Все / Зашли / Не зашли / Ожидают).
Сводка сверху пересчитывается под выбранный период. Кнопка в шапке выгружает CSV.

### Логи
Живой журнал с уровнями Info / Warning / Error, поиском по тексту, экспортом и
очисткой. Обновляется автоматически.

### Статистика
Всего прогнозов, hit rate, число матчей, разбивка по видам ставок
(«Партия 1 · П1/П2», «Партия 1 · ТБ/ТМ» и т.д.), список прогнозов с результатами
по каждой партии, блок экспорта.

### Конструктор
Свой алгоритм прогнозов вместо встроенного ансамбля. Здесь задаются правила вида
«ЕСЛИ … И/ИЛИ … ТО прогноз».

- **Источник прогнозов** — переключатель «Встроенный алгоритм / Конструктор».
  В режиме конструктора движок шлёт только то, что разрешили ваши правила.
- **Правило** = набор условий (группы можно вкладывать, логика «И»/«ИЛИ») и
  действие: **тотал партии** (ТБ/ТМ с любым порогом), **победитель партии**
  (П1/П2) или **пропустить матч**. Дополнительно: название, приоритет,
  «остановить проверку после правила», уверенность, выбор партий (1–5 или авто).
- **Метрики** (~70) с параметрами: очные встречи (серии, проценты, тоталы,
  последний победитель, число партий, разрывы, сколько дней назад), форма игрока
  за N последних игр (победы, тоталы матчей и партий, проценты ТБ, сеты, тренды),
  сравнение игроков между собой, коэффициенты (П1, П2, отношение, вероятность),
  сам матч (час, день недели, минуты до старта, счёт) и таблица «Тотал 75.5» со
  страницы статистики.
- Любое число можно **сравнить с другой метрикой** («сравнить с метрикой»),
  а не только с константой.
- **Шаблоны** — готовые правила в один тап; **Тест на линии** прогоняет правила
  по текущей линии и показывает, что бы сработало и какой прогноз вышел бы,
  ничего не отправляя; **Экспорт/Импорт** правил в JSON.

Статистика круга: число правил, включённых, срабатываний и пропусков.

Данные статистики, на которых работают правила: **5 последних игр каждого игрока**
(счёт по партиям, соперники, даты) и **до 10 очных встреч** со страницы Betcity.

### Анализатор
Разбор уже сделанных прогнозов: какие параметры статистики чаще совпадают
с **неудачными** прогнозами, а какие — с **успешными**. Нужен, чтобы настраивать
правила конструктора по фактам, а не на глаз.

- Снимок статистики (очные встречи, форма обоих игроков, тоталы страницы,
  коэффициенты) сохраняется **в момент отправки** прогноза — поэтому анализатор
  видит именно те данные, что были у движка, когда он давал прогноз.
- Сверху — счётчики: сколько прогнозов с результатом, сколько зашло и не зашло,
  сколько снимков статистики сохранено.
- Фильтры: вид прогноза (все / победитель / тотал), партия (1–5), минимум
  наблюдений в группе (3/5) и минимальный перевес между группами.
- **Неудачные прогнозы** — список условий с долями: «неудачи 12 из 12 · удачи 0%
  · перевес −100 п.п.». **Успешные** — то же с обратным знаком. У каждого условия
  видны примеры матчей и кнопка **«В конструктор»**.
- **Связки из двух условий** — пары параметров, которые срабатывают вместе.
- **Средние значения** — среднее у зашедших против незашедших по каждой метрике
  (сортировка по силе различия).
- «В конструктор» переносит условие в редактор правила. Из блока неудач условие
  **инвертируется** (≤ → >, = → ≠), чтобы правило исключало плохую ситуацию;
  из блока удач — переносится как есть. Остаётся задать действие и сохранить.
- Экспорт анализа — JSON со всеми найденными условиями.

Анализатор работает на прогнозах, сохранённых начиная с версии 1.3: у более
ранних прогнозов статистика не сохранялась, и они в разбор не попадают.

### Настройки
Все параметры движка:

- **источник прогнозов** — встроенный алгоритм или конструктор;
- интервал опроса линии (5–600 с);
- проверка коэффициентов, подробный лог, размер ставки;
- Telegram: включение, токен, chat id;
- пороги шести моделей (streak, window, markov1, markov2, recency, base_rate);
- обязательные модели;
- виды ставок (П1, П2, ТБ 18.5, ТМ 18.5) и партии (1–5);
- общие фильтры: согласные модели, согласие, уверенность, активные модели,
  вес голоса, минимум очных встреч;
- параметры моделей: серия, окно, попадания, выборка Маркова, затухание
  свежести, выборка базовой частоты;
- отчёты: ежечасный, дневной (час и минута);
- уведомления: сигнал, результат, ошибки;
- очистка данных.

Кнопка «Сохранить настройки» применяет изменения сразу — перезапуск не нужен.

## Экспорт

| Кнопка | Формат | Содержимое |
|---|---|---|
| Отчёт | `.txt` | Сводка: всего, успешные, неудачные, hit rate, разбивка |
| Результаты | `.csv` | История игр: прогноз, обоснование, результат, счёт, тотал |

| Настройки | `.json` | Текущие настройки |

или отправить в облако/мессенджер.

## Telegram (необязательно)

Без токена приложение полностью работает: прогнозы, результаты и статистика
хранятся локально, а сигналы показываются уведомлением.

Если нужны сообщения в чат:

1. Создайте бота у `@BotFather`, получите токен.
2. Узнайте свой chat id (например, через `@userinfobot`).
3. Впишите оба значения в Настройки → Telegram и включите переключатель.

После сохранения бот переключается на отправку без перезапуска приложения.

## Как это работает

```
Android UI (WebView)
        │  window.PyApp.*
        ▼
MainActivity.kt  ──►  engine_api.py  ──►  predictor_core.py
        │                                      │
        │                                      ├─ Betcity API (линия)
        │                                      ├─ betcity.by/ru/mstat (статистика:
        │                                      │      5 игр игрока + очные + тоталы)
        │                                      ├─ constructor_engine.py (правила)
        │                                      └─ predictor_data/ (настройки, логи, CSV)
        ▼
EngineService (foreground) — не даёт системе выгрузить процесс
```

Движок работает в одном из двух режимов (переключатель в «Настройках» и в
«Конструкторе»): **встроенный** — ансамбль шести моделей, как в оригинальном
скрипте, или **конструктор** — только правила пользователя.

Данные лежат в приватной папке приложения:
`/data/data/by.betcity.predictor/files/predictor_data/`
(правила конструктора — `constructor_rules.json`).

Запуск движка поднимает foreground-сервис с постоянным уведомлением — Android
не убивает процесс, пока идёт анализ. После перезапуска процесса сервис
автоматически поднимает движок, если он был включён.

## Сборка из исходников

Нужны JDK 17, Android SDK 34 и Python 3.13.

```powershell
$env:ANDROID_HOME="C:\Android"
cd betcity-predictor-android
C:\Android\gradle-8.7\bin\gradle.bat assembleDebug
```

Результат: `app/build/outputs/apk/debug/app-debug.apk`.

### Структура

```
app/src/main/python/
  predictor_core.py   движок (порт 17allsets.py)
  constructor_engine.py  правила конструктора (метрики, условия, действия)
  engine_api.py       JSON-API для Kotlin и JS
  requests/, bs4/, …  вендоренные чистые Python-пакеты
app/src/main/java/by/betcity/predictor/
  MainActivity.kt     WebView, мост в Python, сохранение файлов
  EngineService.kt    foreground-сервис и уведомления
app/src/main/assets/www/
  index.html, style.css, app.js
```

`requests`, `beautifulsoup4` и их зависимости лежат прямо в `python/` —
pip при сборке не используется (резолвер на этой машине зависал, а нативные
колёса этим пакетам не нужны).

## Отличия от исходного скрипта

1. **Telegram не обязателен** — хранилище прогнозов работает всегда.
2. **Данные** пишутся в приватную папку приложения, а не в текущий каталог.
3. **Цикл** управляется кнопками: старт, стоп, ручная проверка.
4. **Логи** идут в кольцевой буфер (2000 событий) и файл `predictor.log`.
5. **Исправлены два бага оригинала:**
   - результаты «победитель» и «тотал» одной партии перезаписывали друг друга;
   - счёт через пробел (`11:7 9:11`) не разбирался.
6. Логика моделей, фильтров и парсинга сохранена.

Дополнительно в приложении:

7. **Конструктор правил** — свой алгоритм прогнозов: условия по статистике
   (5 последних игр игрока, очные встречи, коэффициенты, тоталы) и действия
   (ТБ/ТМ, П1/П2, пропуск). Режим выбирается переключателем.
8. **Статус-бар** всегда скрыт, а его цвет (если система его покажет) совпадает
   с фоном приложения.
9. **Очередь и результаты** дополнены показом прогноза, обоснования и итога
   по каждой партии (в том числе для прогнозов конструктора).
