# Тесты

Портативные копии регрессий проекта. Работают из корня
`betcity-predictor-android`, не требуют установленного приложения. `HOME`
подменяется на `%TEMP%\predictor-tests\...`, рабочие данные пользователя не
затрагиваются.

## Быстрый запуск

```powershell
$env:PYTHONUTF8="1"; $env:PYTHONIOENCODING="utf-8"
python tests\run_all.py --offline
```

Полный набор с сетевыми проверками Betcity:

```powershell
python tests\run_all.py
```

С медленными live-циклами:

```powershell
python tests\run_all.py --live
```

PowerShell может показать `RequestsDependencyWarning` и завершиться с кодом 1
даже при успешном тесте. Ориентируйтесь на итоговую строку `OK` /
`ВСЕ ПРОВЕРКИ ПРОЙДЕНЫ` / `ALL SELECTED TESTS PASSED`.

### Сеть

| Файл | Что проверяет |
|---|---|
| `test_constructor_backend.py` | API конструктора, тест на live-линии |
| `test_engine_e2e.py` | полный API, очередь, запуск/остановка, экспорт |

Эти тесты зависят от доступности `d.betcity.by` и могут падать при
блокировке сети. Это не ошибка кода.

### Живые циклы

| Файл | Что делает |
|---|---|
| `test_full_cycle.py` | реальный `run_cycle`, отправка, сохранение файлов |
| `test_live_analysis.py` | реальный матч и разбор статистики |

Медленные, без строгих assert'ов, нужны для ручной диагностики.

## Фикстуры

```text
tests/fixtures/
  stats_page.html          страница статистики TT
  sport_probe/
    football_1..3.html
    hockey_1..3.html
    basketball_1..3.html
    volleyball_1..3.html
    tennis_1..3.html
```

`stats_page.html` и `sport_probe` — снимки реальных страниц Betcity. Они
позволяют проверять парсеры без сети. Не удаляйте и не редактируйте их без
причины: тесты ожидают конкретные значения.

## Правила добавления тестов

1. Тест должен сам создавать временный `HOME` и не трогать `predictor_data`.
2. Пути — только от `ROOT` / `FIXTURES`, без абсолютных путей машины.
3. Сеть — только в разделе «Сеть»/«Живые циклы».
4. Для проверок используйте явные сообщения `PASS/FAIL` и итоговую строку.
5. Добавьте файл в `run_all.py` и в таблицу выше.
