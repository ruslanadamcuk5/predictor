# UI — WebView-интерфейс

## 1. Устройство

Интерфейс — статический WebView:

```text
app/src/main/assets/www/
  index.html   разметка экранов и модалок
  style.css    тема, сетка, карточки, чипы
  app.js       состояние, вызовы PyApp, рендер
  docs.js      контент встроенной документации (window.APP_DOCS)
```

Никакого сборщика, npm и фреймворка нет. JS загружается как есть. Все данные
приходят строками JSON из `window.PyApp.*`; `call()` делает `JSON.parse`.

```js
function call(name, ...args) {
  const raw = bridge[name](...args);
  return raw ? JSON.parse(raw) : null;
}
```

Если моста нет (браузерный стенд), `call` пишет предупреждение и возвращает
`null`. Для стенда подменяйте `window.PyApp` заглушкой.

## 2. Экраны и навигация

Нижняя навигация, 9 кнопок с короткими подписями (сетка
`repeat(9, minmax(0, 1fr))`; подпись «Документация» переносится по мягкому
дефису):

| `data-screen` | Подпись | Назначение |
|---|---|---|
| `dashboard` | Панель | статус, кнопки, счётчики, события |
| `queue` | Очередь | live-линия и прогнозы |
| `results` | Результаты | история и фильтры |
| `logs` | Логи | журнал |
| `stats` | Статистика | сводка по видам/рынкам |
| `constructor` | Правила | конструктор |
| `analyzer` | Анализ | анализатор |
| `settings` | Настройки | параметры |
| `docs` | Докумен­тация | встроенное руководство |

`navigate(screen)` переключает `.screen.active` и нижнюю кнопку. Статус-бар
Android скрыт в `MainActivity`; учитываются `safe-area-inset-*`.

## 4. Мост Kotlin ↔ JS

`MainActivity.Bridge` — единственный интерфейс. Все методы синхронные и
возвращают строку JSON. При ошибке Python возвращается
`{"ok": false, "error": "..."}`.

| JS | Kotlin | Python |
|---|---|---|
| `state()` | `state()` | `api_state` |
| `start()` | `start()` | `api_start` + `EngineService` |
| `stop()` | `stop()` | `api_stop` + `EngineService` |
| `runOnce()` | `runOnce()` | `api_run_once` |
| `version()` | `version()` | `api_version` |
| `settings()` | `settings()` | `api_settings` |
| `saveSettings(json)` | `saveSettings` | `api_save_settings` |
| `resetSettings()` | `resetSettings` | `api_reset_settings` |
| `setSport(id)` | `setSport` | `api_set_sport` |
| `logs(sinceId, limit, level, search)` | `logs` | `api_logs` |
| `clearLogs()` | `clearLogs` | `api_clear_logs` |
| `errors(limit)` | `errors` | `api_errors` |
| `queue()` | `queue` | `api_queue` |
| `refreshQueue()` | `refreshQueue` | `api_refresh_queue` |
| `clearProcessed()` | `clearProcessed` | `api_clear_processed` |
| `predictions(limit, sport)` | `predictions` | `api_predictions` |
| `results(start, end, search, status, limit, sport)` | `results` | `api_results` |
| `constructor(sport)` | `constructor` | `api_constructor` |
| `saveConstructor(json)` | `saveConstructor` | `api_save_constructor` |
| `setAlgorithmMode(mode)` | `setAlgorithmMode` | `api_set_algorithm_mode` |
| `testConstructor(payload, limit)` | `testConstructor` | `api_test_constructor` |
| `analyzer(payload)` | `analyzer` | `api_analyzer` |
| `stats()` | `stats` | `api_stats` |
| `resetStats()` | `resetStats` | `api_reset_stats` |
| `testConnection()` | `testConnection` | `api_test_connection` |
| `exportData(kind)` | `exportData` | `api_export` |
| `clearData(what)` | `clearData` | `api_clear_data` |
| `platform()` | `platform` | — (Kotlin) |

Особенности:

- `saveConstructor` и `testConstructor` **не принимают sport отдельным
  аргументом**: вид передаётся внутри JSON (`sport`). Python также умеет
  брать активный вид.
- `results` принимает `sport=""` — все виды, иначе id вида.
- `predictions` с `sport=""` — все виды.
- `api_set_sport` меняет глобальную настройку и возвращает
  `{ok, sport, name}`.
- Мост ловит исключения и не роняет WebView.

**Важно:** вызовы синхронные, выполняются в UI-потоке. Не вызывайте их в
циклах по сотням элементов и не делайте тяжёлых запросов без loader.

## 5. Активный вид спорта в UI

Активный вид — это только выбор интерфейса (какие правила, шаблоны и каталог
метрик показывать). Движок анализирует линию всех видов сразу, поэтому
переключение вида **не ограничивает** прогнозы, очередь и результаты.

Есть два уровня:

1. **Глобальный активный вид** — `state.sport`.
   - Верхняя спортивная панель `sportBar`;
   - чипы в конструкторе `ctorSports`;
   - чипы в настройках `setSports`.
   Все три вызывают `setActiveSport(id)` → `PyApp.setSport` → backend.
   После смены:
   - обновляются `state.sport`, `state.sportName`;
   - очищается очередь;
   - сбрасывается фильтр результатов;
   - сбрасывается фильтр анализатора;
   - перезагружаются конструктор, очередь, результаты, статистика.

2. **Локальные фильтры**:
   - `resSport` — фильтр истории, `""` = все виды;
   - `anSport` — `""` = активный вид, `"all"` = все виды, иначе конкретный.
   Локальные фильтры **не меняют** глобальный активный вид.

`renderSportSelectors()` перерисовывает все селекторы. Если добавляете новый
экран с видом спорта, добавьте его контейнер сюда и в `bind()`.

### Зависимости от вида в UI

- В настройках карточки порогов моделей, обязательных моделей, ставок и партий
  показываются только для настольного тенниса; для остальных — пояснение
  `cardTeamNote`.
- В конструкторе набор метрик, сторон, рынков и целей берётся из
  `catalog.metrics`, `catalog.bets`, `catalog.side_labels`.
- В анализаторе:
  - `Матч` скрыт для настольного тенниса;
  - `Партии` скрыты для командных видов;
  - `Фора` показывается, если рынок есть у вида;
  - `Обе забьют` — только футбол/хоккей;
  - при `anSport = ""` используется активный вид; при `"all"` показываются
    все цели и рынки.

## 6. Очередь

`state.queueFilter`:

- `all` — все;
- `upcoming` — не начались и не обработаны;
- `sent` — есть отправленный прогноз;
- `processed` — обработаны.

Карточка содержит:

- вид спорта (badge);
- команды, лигу, время;
- счёт;
- коэффициенты П1/X/П2 и тотал;
- статус;
- для `sent` — прогноз и результат по матчу.

`refreshQueue()` вызывает `api_refresh_queue` (сеть) и обновляет
`state.queue`. `get_queue` не ходит в сеть, а отдаёт кэш.

Очередь содержит матчи **всех видов**: у каждой карточки свой badge вида, а
заголовок показывает «Все виды», если в очереди больше одного вида
(`renderQueue()` считает `new Set(state.queue.map(m => m.sport))`).

## 7. Результаты

`state.resultsFilter`:

```js
{from: '', to: '', search: '', status: 'all', sport: ''}
```

- `from` / `to` — datetime-local; пустое значение не ограничивает.
- `status`: `all`, `win`, `loss`, `pending`. `win` — есть победы и нет
  поражений; `loss` — есть хотя бы одно поражение; `pending` — есть
  непроверенные прогнозы.
- `search` — команды, лига, id.
- `sport`: `""` — все.

Быстрые диапазоны: сегодня, 7 дней, 30 дней, всё время. Фильтр применяется
на backend; UI только передаёт параметры. `refreshResults()` не чаще раза в
10 секунд на экране результатов.

Карточка результата показывает:

- команды, лигу, дату/время, счёт;
- вид спорта;
- каждый прогноз: label, verdict, статус, обоснование;
- итог: зашло / не зашло / возврат / ожидает;
- сводку и CSV-экспорт.

## 8. Логи

- Уровни: `info`, `warning`, `error`, `success`.
- `logs(sinceId, limit, level, search)` возвращает `items`, `last_id`,
  `total`.
- UI хранит `logsSince`; при очистке сбрасывает в 0.
- `debug_verbose` включает подробности моделей/парсинга.
- Ошибки — отдельная вкладка/блок через `errors(limit)`.

## 9. Статистика

`api_stats` агрегирует `sent_predictions`:

- всего прогнозов, матчей, hit rate;
- по видам спорта;
- по рынкам (`match:total`, `set1:winner` и т.п.);
- последние прогнозы.

`refreshStats()` вызывается при открытии экрана и после смены вида.

## 11. Конструктор

- Список правил с приоритетом, статусом, сводкой.
- Переключатель `builtin` / `constructor`.
- Модалка правила:
  - имя, включено, приоритет, stop;
  - дерево условий (И/ИЛИ, вложенность);
  - аргументы метрики;
  - оператор и значение/вторая метрика;
  - рынок, сторона, тотал/фора, цели, уверенность.
- Шаблоны с категориями и поиском.
- «Тест на линии» — `testConstructor` с текущими правилами.
- Импорт/экспорт JSON.
- Кнопка «?» ведёт в статью документации о полях правила.

`openRuleEditor(index, prefill)` умеет не только создавать правило, но и
дополнять существующее: при `prefill.append` условия добавляются в корневую
группу `conditions.conditions` (логика «И»), выставляется `attachNotice`, а
после сохранения — `highlightId`. Если правило относится к другому виду,
`ensureSportThen` сначала переключает активный вид и загружает его каталог.

При смене вида редактор закрывается/перерисовывается, чтобы не смешать
метрики разных видов.

## 12. Анализатор

- Фильтры вида, рынка, цели, минимальной группы, перевеса.
- Две колонки: неудачи и успехи.
- Раскрывающиеся строки с условиями, долями, примерами.
- «В конструктор» открывает `attachModal`: превью условия, чипы вида спорта,
  «＋ Создать новое правило» и список существующих правил.
- Для неудач оператор инвертируется (`≤ → >`, `= → ≠` и т.п.); для удач
  условие переносится как есть. Дубликаты в целевом правиле пропускаются.
- Перед показом кнопок проверяется, что метрика есть в каталоге выбранного
  вида спорта (`attachCompatibility`); иначе выводится предупреждение.
- `limit` по умолчанию 0 (все наблюдения).
- Карточка `anAutoCard`: бейдж вкл/выкл, сводка (правил, наблюдений, порог,
  время), кнопки «Включить/Выключить авто», «Обновить сейчас», «В конструктор»,
  чипы точности (55/60/70/80%) и наблюдений (4/6/10/15).
- Список авто-правил: имя, точность, полоса точности, действие, срабатывания,
  удачи/неудачи, покрытие и кнопка «Открыть в конструкторе» (ставит
  `state.ctor.highlightId` и переходит на экран правил).
- `loadAutoStatus()` вызывается после `refreshAnalyzer()` и при смене вида;
  действия — `autoToggle`, `autoRefresh`, `autoConfigure`, `openAutoRule`.
- Пока идёт запрос, `state.an.autoBusy` блокирует кнопки, чтобы не запускать
  два пересчёта одновременно.

## 13. Документация

Экран `screen-docs` — две области: `docsHome` (hero, поиск, фильтры, быстрые
ссылки, список статей) и `docsArticle` (заголовок, оглавление, секции,
навигация). Контент лежит в `docs.js`:

```js
window.APP_DOCS = {
  version: '1.7.0',
  groups: [{id, title, icon}],
  kinds: [{id, title}],
  articles: [{
    id, title, group, kind, summary, tags: [],
    sections: [{id, title, html}],
  }],
};
```

- `renderDocsHome()` фильтрует статьи по группе, типу и поиску. Поиск идёт по
  заголовку, summary, тегам и тексту секций (HTML очищается), совпадения
  подсвечиваются через `<mark>`, в карточке показываются сниппеты.
- `openDoc(id)` рендерит статью, строит оглавление по `sections`, ставит
  историю для `appBack()`. `appBack()` из статьи возвращает к списку.
- Статья `reference-metrics` — динамическая: `loadDocMetrics(sport)` вызывает
  `constructor(sport)` (без смены активного вида), кэширует каталог в
  `state.docs.catalogs` и рисует метрики с поиском и группировкой.
- Кнопки `[data-doc]` в конструкторе, анализаторе и hero открывают нужную
  статью; `[data-doc-sport]`, `[data-doc-article]` — переключатели.
- Контент вставляется как доверенный HTML из `docs.js`; пользовательские
  данные в него не попадают. Динамические названия метрик проходят `esc()`.

## 14. Безопасность и стиль

- Все динамические строки вставляются через `esc()`; не используйте
  `innerHTML` с сырыми данными API.
- Никаких внешних CDN: приложение должно работать офлайн, кроме Betcity.
- Тема — тёмная, токены в `:root`:
  `--bg #0f1115`, `--card #191d27`, `--line #262c3a`,
  `--text #e8ebf2`, `--muted #8b93a7`, `--accent #e23b4e`,
  `--ok #35c48a`, `--bad #e2585f`, `--warn #e0a23c`.
- Радиусы 18/12 px, safe-area, горизонтальный скролл спортивной панели.
- Кнопки должны иметь понятную подпись и состояние disabled/loading.
- Основной текст — не меньше 12–13 px; подписи нижнего меню при 9 колонках —
  7.5 px, поэтому они короткие, а «Документация» переносится.
- Документация использует те же токены: карточки, чипы, таблицы в
  `.doc-table-wrap` с горизонтальным скроллом, выноски info/warn/ok.

## 15. Периодичность обновлений

В `startPolling()`:

- статус — раз в 5 секунд вне панели;
- результаты — раз в 10 секунд на экране результатов;
- конструктор — раз в 15 секунд, если не открыт редактор.

Логи/очередь обновляются по действию или при открытии, чтобы не грузить
UI-поток.

## 16. Браузерный стенд

Для проверки без телефона используется отдельная копия `www` с
`mock.js`, подменяющим `window.PyApp`. Стенд не входит в APK. Если он нужен,
соберите его из `tools/ui_harness/` (см. `TESTING.md`) и откройте
`index.html` в браузере. `sync_ui.py` копирует `index.html`, `app.js`,
`docs.js` и `style.css`. Проверяйте консоль: ошибок быть не должно.

Что смотреть в стенде для 1.13:

- карточка «Нейросеть» на панели: бейдж, объём данных, точность по видам,
  кнопки «Включить прогнозы», «Обучить сейчас», «Сбросить»;

  правки; после применения правило меняется в конструкторе, анализ
  обновляется;
