# CONSTRUCTOR — конструктор правил

## 1. Что это

Конструктор заменяет встроенный алгоритм пользовательскими правилами вида

```text
ЕСЛИ <группа условий> ТО <прогноз> [ИНАЧЕ пропустить]
```

Правила хранятся отдельно для каждого вида спорта. Одно правило может дать
один или несколько прогнозов (по партиям или по нескольким целям). Режим
включается в настройках: `algorithm_mode = "constructor"`.

## 2. Схема правила

```json
{
  "id": "r_a1b2c3d4e5",
  "name": "ТБ по средней форме",
  "sport": "football",
  "enabled": true,
  "priority": 100,
  "stop": false,
  "conditions": {
    "logic": "and",
    "conditions": [
      {
        "metric": "p.recent.avg_match_total",
        "args": {"side": "p1", "window": 5},
        "op": "gte",
        "value": 2.5
      }
    ]
  },
  "action": {
    "type": "total",
    "targets": ["match"],
    "side": "over",
    "threshold": 2.5,
    "confidence": 0.62
  }
}
```

### Поля правила

| Поле | Тип | Смысл |
|---|---|---|
| `id` | string | генерируется автоматически |
| `name` | string | имя в UI и логах |
| `sport` | string | при сохранении приводится к виду из запроса |
| `enabled` | bool | выключенные правила не оцениваются |
| `priority` | int | больше — раньше; по умолчанию 100 |
| `stop` | bool | остановить перебор после срабатывания |
| `conditions` | object | корневая группа |
| `action` | object | что прогнозировать |
| `auto` | bool | правило создано авто-генератором |
| `auto_key` | string | стабильный ключ действия + условий |
| `auto_kind`, `auto_target` | string | рынок и цель для перепроверки |
| `auto_source` | string | `success`, `failure` или `mixed` |
| `auto_stats` | object | точность, покрытие, `n`, удачи/неудачи, время |

Ограничения: не более **200 правил** на вид, не более **50 условий** в одной
группе, глубина вложенности — **6**. При ошибках сохранение отклоняется
целиком и возвращает список ошибок.

Авто-правила создаёт `auto_rules.py`. `_clean_rule` сохраняет служебные поля
только при `auto: true`. Генератор заменяет лишь правила с `auto`, поэтому
ручные правила не удаляются и не перезаписываются. Если пользователь вручную
отредактировал авто-правило, UI сохранит его без `auto`, и оно станет обычным.

## 3. Группы условий

Группа:

```json
{"logic": "and", "conditions": []}
```

- `logic`: `"and"` или `"or"`.
- Элемент — либо условие (есть ключ `metric`), либо вложенная группа.
- Пустая группа считается истинной.

Условие:

```json
{
  "metric": "h2h.avg_total",
  "args": {"window": 10},
  "op": "gte",
  "value": 2.5,
  "value2": 3.5,
  "value_metric": "p.recent.avg_match_total",
  "value_args": {"side": "p1", "window": 5}
}
```

- `args` дополняются значениями по умолчанию из описания метрики.
- `value_metric` позволяет сравнивать две метрики; если метрика недоступна
  для вида, сравнение идёт с числом `value`.
- `between` использует `value` и `value2`.
- Для `in` / `not_in` строку можно передать как `"a,b,c"` — backend разобьёт
  её на список.

### Операторы

| Тип метрики | Операторы |
|---|---|
| number | `gt`, `gte`, `lt`, `lte`, `eq`, `neq`, `between`, `exists`, `not_exists` |
| string | `eq`, `neq`, `contains`, `not_contains`, `in`, `not_in`, `starts_with`, `ends_with`, `exists`, `not_exists` |
| enum | `eq`, `neq`, `in`, `not_in`, `exists`, `not_exists` |
| bool | `is`, `exists`, `not_exists` |

Сравнение строк и enum — без учёта регистра и пробелов по краям. Числовое
`eq` — с допуском `1e-9`.

### Аргументы

| Аргумент | Значения | По умолчанию |
|---|---|---|
| `side` | `p1`, `p2` | `p1` |
| `window` | 1..20 (в UI по умолчанию 5) | 5 |
| `set` | 1..5 | 1 |
| `threshold` | число | 18.5 |

Метрики с `side` оцениваются для выбранного игрока/команды. Метрики H2H
обычно не имеют `side` и смотрят на всех соперников.

## 4. Действия

```json
{
  "type": "total | winner | handicap | btts | skip",
  "targets": ["match"] | [1,2,3,4,5] | ["auto"],
  "side": "auto | p1 | p2 | over | under | x | yes | no",
  "threshold": 2.5,
  "value": -1.5,
  "confidence": 0.6,
  "scope": "match | set"
}
```

`scope` выставляется backend: `match` для всех видов, кроме настольного
тенниса; `set` для настольного тенниса.

### Победитель (`winner`)

- Настольный теннис: `p1` / `p2` по партии.
- Футбол/хоккей: `p1` / `p2` / `x`.
- Баскетбол/волейбол/теннис: `p1` / `p2`.
- `auto` выбирает сторону по форме, H2H и (для видов с ничьей) draw rate.

### Тотал (`total`)

- `over` / `under` / `auto`.
- `threshold` — линия. Если не задана или `0`, для матча берётся линия
  коэффициентов Betcity, затем `page_total.line`, затем `default_total`.
- Для настольного тенниса — тотал партии.

### Фора (`handicap`)

Только командные виды и теннис. `value` хранится со знаком и уже привязан к
стороне:

- Ф1 `-1.5` → `value = -1.5`, `side = "p1"`;
- Ф2 `+1.5` → `value = +1.5`, `side = "p2"`.

Расчёт:

```text
m = score_p1 - score_p2
Ф1: m + value
Ф2: -m + value
```

`0` — возврат, `success = null`. Положительный результат — зашла.

### Обе забьют (`btts`)

Только футбол и хоккей. `yes` / `no`; `auto` выбирает по H2H и форме.

### Пропуск (`skip`)

Сбрасывает все прогнозы, накопленные этим матчем, и останавливает перебор.
Используется как жёсткий фильтр.

## 5. Автовыбор

### Партия (настольный теннис)

`targets = ["auto"]`: перебираются партии 1..5 и допустимые стороны; выбирается
комбинация с максимальной исторической долей успеха. Если данных нет —
партия 1 и `p1`/`over`.

### Сторона матча

`side = "auto"`:

- `winner`: взвешенная форма P1/P2 + H2H; для видов с ничьей при draw rate
  ≥ 30% и разнице < 15 п.п. выбирается `x`;
- `total`: сравнивает средние тоталы и линию;
- `handicap`: выбирает сторону по форме/H2H и средней разнице;
- `btts`: сравнивает H2H-частоту и форму.

## 6. Порядок оценки

1. Берутся включённые правила вида.
2. Сортировка по `priority` по убыванию (стабильная для равных).
3. Для каждого правила вычисляется группа условий.
4. Если условия ложны — правило пропускается.
5. Если `skip` — очищает прогнозы и прерывает цикл.
6. Иначе создаются прогнозы для целей.
7. Если `stop = true` — цикл прерывается после этого правила.
8. Среди прогнозов с одинаковой парой `(target, kind)` остаётся прогноз с
   максимальной `confidence_val`.
9. Результат сортируется по `(target, kind)`.

Счётчики: `matches` (оценок), `fired` (срабатываний), `skipped`, `rules`
(включённых правил).

## 7. Уверенность

`action.confidence` по умолчанию `0.6`, ограничена диапазоном `0.05..0.99`.
Она попадает в `confidence_val` и `min_model_wilson`. Конструктор не
пересчитывает её из статистики: это заявленная пользователем уверенность,
используемая для сортировки и отображения.

## 8. Метрики

Каждая метрика описана в `METRICS`:

```python
{
  "id": "h2h.avg_total",
  "label": "Средний тотал H2H",
  "group": "H2H",
  "type": "number",
  "args": {"window": {"kind": "number", "default": 10}},
  "unit": "",
  "hint": "..."
}
```

Группы метрик:

- `Форма` — последние игры P1/P2;
- `Сравнение формы` — разницы и соотношения;
- `Коэффициенты` — линии и цены;
- `Матч` — время, счёт, лига, текущее состояние;
- `Статистика со страницы` — тоталы со страницы Betcity;
- `H2H` — очные встречи.

Полный каталог:

```text
docs/ai/generated/metrics/<sport>.json
```

### Правила доступности

- `SET_METRIC_IDS` — не для футбола;
- `DRAW_METRIC_IDS` — только виды с ничьей;
- `BTTS_METRIC_IDS` — только футбол и хоккей;
- `GENERIC_EXTRA_IDS` — не для настольного тенниса.

Не добавляйте метрику в `METRICS`, не описав её аргументы, тип, единицу и
подпись. Не забывайте про `SPORT_METRIC_IDS`: `validate_metric_for_sport()`
должен отклонять недоступные метрики.

## 9. Шаблоны

- `PRESETS` — 46 шаблонов настольного тенниса.
- `SPORT_PRESETS[sport]` — 10–12 шаблонов командных видов и тенниса.
- `presets_for(sport)` — единая точка.
- `apply_preset(rule, preset)` — копирует условия и действие, сохраняя имя.

Все шаблоны проходят `_clean_rule` при сохранении. Полные данные:

```text
docs/ai/generated/presets/<sport>.json
```

Шаблон — не гарантия. Перед включением проверьте его на линии и в анализаторе.

## 10. Хранение

`ConstructorEngine(path, settings, logger)`:

| Вид | Файл |
|---|---|
| Настольный теннис | `constructor_rules.json` |
| Футбол | `constructor_rules_football.json` |
| Хоккей | `constructor_rules_hockey.json` |
| Баскетбол | `constructor_rules_basketball.json` |
| Волейбол | `constructor_rules_volleyball.json` |
| Теннис | `constructor_rules_tennis.json` |

`_load_file` терпит старый формат: если в файле просто список правил, он
принимается. При загрузке каждое правило заново нормализуется; битые правила
пропускаются с записью в лог.

Сохранение атомарное: `path.tmp` → `os.replace`. При ошибке файл не
перезаписывается, UI получает `ok: false` и список ошибок.

## 11. API

- `api_constructor(sport)` — каталог, правила, шаблоны, статистика.
- `api_save_constructor(json, sport)` — сохранить.
- `api_test_constructor(json, limit, sport)` — прогнать правила на текущей
  линии и вернуть срабатывания.
- `api_set_algorithm_mode(mode)` — `builtin` / `constructor`.

Все ответы — JSON-строки. Подробные сигнатуры:
`docs/ai/generated/api_endpoints.json`.

## 12. UI-редактор

В `app.js`:

- `renderConstructor` — список правил, чипы вида, кнопки;
- `openRuleEditor` / `saveRuleEditor` — модалка;
- `renderConditionHTML` — условие и его аргументы;
- `renderActionExtra` — рынок, сторона, тотал, фора, цели, уверенность;
- `addPreset` / `renderPresetList` — шаблоны;
- `testRules` / `renderTestResults` — тест на линии.

При смене вида редактор полностью перерисовывается: набор метрик, сторон,
рынков и целей зависит от вида. Не сохраняйте правило одного вида в файл
другого.

### Подводные камни

- У настольного тенниса `targets` — партии 1..5 или `auto`; у остальных —
  только `match`.
- У футбола/хоккея есть `x`, у баскетбола/волейбола/тенниса — нет.
- `btts` нельзя добавить баскетболу, волейболу, теннису, настольному теннису.
- Фора хранится со знаком; не «нормализуйте» её в положительное число.
- При `stop` порядок правил меняет результат — проверяйте приоритеты.
- Пустая группа условий истинна; это удобно для отладочных правил, но опасно
  в продакшене.
