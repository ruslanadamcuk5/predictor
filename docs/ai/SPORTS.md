# SPORTS — виды спорта

## 1. Принцип

`active_sport` — одна глобальная настройка. Она определяет:

- какую линию получает движок;
- какой каталог метрик и шаблонов показывает конструктор;
- какие рынки доступны правилам;
- какой фильтр по умолчанию у очереди, статистики и анализатора;
- какие прогнозы считает встроенный алгоритм.

Правила и шаблоны каждого вида хранятся отдельно. Переключение вида не удаляет
и не перезаписывает правила других видов.

## 2. Каталог

| id | Название | Betcity id | Тотал по умолчанию | Тотал матча | Margin | Ничья | Период | Периодов | Рынки |
|---|---|---|---:|---:|---:|---|---|---:|---|
| `table_tennis` | Настольный теннис | 46 | 18.5 | 75.5 | 1.5 | нет | Партия | 7 | winner, total |
| `football` | Футбол | 1 | 2.5 | 2.5 | 0.4 | да | Тайм | 2 | winner, total, handicap, btts |
| `hockey` | Хоккей | 7 | 5.5 | 5.5 | 0.8 | да | Период | 3 | winner, total, handicap, btts |
| `basketball` | Баскетбол | 3 | 160.5 | 160.5 | 6.0 | нет | Четверть | 4 | winner, total, handicap |
| `volleyball` | Волейбол | 12 | 179.5 | 179.5 | 7.0 | нет | Партия | 5 | winner, total, handicap |
| `tennis` | Большой теннис | 2 | 20.5 | 20.5 | 1.5 | нет | Сет | 5 | winner, total, handicap |

`margin` — минимальное отклонение среднего тотала от линии, при котором
generic-алгоритм выдаёт ТБ/ТМ. Для настольного тенниса — 1.5 очка, для
футбола — 0.4 гола и т.д.

`default_total` — линия по умолчанию для шаблонов и правил, если Betcity не
дал тотал. `match_total` — справочный тотал матча для настольного тенниса.

## 3. Live API

Один endpoint для всех видов:

```text
GET https://d.betcity.by/api/v1/live/bets
    ?rev=8&add=dep_event&ver=479&csn=lsmif5
```

Нужная секция: `reply.sports[<betcity_id>].chmps[*].evts[*]`.

Из события берутся:

- команды/игроки;
- лига;
- дата/время;
- счёт;
- `stat_link` на `betcity.by/ru/mstat/...`;
- коэффициенты из блоков `main`;
- признаки завершения (`status_ev=4`, `st_ev=3`,
  `time_type_status=-1`, `time_name="Матч завершен"`).

Завершённые события ещё некоторое время остаются в live-фиде — это нужно
учитывать при проверке результатов.

## 4. Счёт

Betcity использует один визуальный формат для всех видов:

| Вид | Пример | Смысл скобок |
|---|---|---|
| Футбол | `3:2 (2:1)` | первый тайм |
| Хоккей | `4:6 (2:4, 0:1, 2:1)` | периоды |
| Баскетбол | `89:99 (22:18, 17:25, ...)` | четверти |
| Волейбол | `3:1 (25:18, 21:25, ...)` | партии и очки в партиях |
| Теннис | `2:0 (7:6, 7:5)` | сеты и геймы в сетах |
| Настольный теннис | `3:2 (11:9, 9:11, ...)` | партии и очки |

`parse_score(sport, text)` в `sports.py` разбирает строку в словарь с полями
`match`, `periods`, `total`, `sets_won`, `winner`, `draw`, `raw`. Для футбола
скобки — только первый тайм, для остальных — все периоды/сеты/партии.
`record_from_score(sport, parsed, flipped=False)` превращает результат в
нормализованную запись. Пример для футбола `3:2 (2:1)`:

```json
{
  "match_score": [3, 2],
  "sets": [[3, 2]],
  "set_totals": [5],
  "match_total": 5,
  "won": true,
  "draw": false,
  "btts": true,
  "winner": "P1"
}
```

Для футбола `sets` содержит один элемент — матч. Для хоккея/баскетбола —
периоды/четверти, для волейбола/тенниса — партии/сеты. `match_total` — это
сумма всех очков/голов/геймов: у волейбола `3:1 (25:18, 21:25, 25:20, 25:19)`
даёт `match_total = 178`, у тенниса `2:0 (7:6, 7:5)` — `25`. `winner` —
`"P1"`, `"P2"` или `"DRAW"`. Это позволяет переиспользовать метрики
настольного тенниса для командных видов.

## 5. Рынки и действия правил

| Тип | Поле `action.type` | Стороны | Дополнительно |
|---|---|---|---|
| Победитель | `winner` | `p1`, `p2`; `x` только при `has_draw` | — |
| Тотал | `total` | `auto`, `over`, `under` | `threshold` |
| Фора | `handicap` | `auto`, `p1`, `p2` | `value` со знаком |
| Обе забьют | `btts` | `auto`, `yes`, `no` | только футбол/хоккей |
| Пропуск | `skip` | — | — |

Для настольного тенниса `targets` — список партий `[1..5]` или `["auto"]`.
Для командных видов `targets` всегда `["match"]`; backend принудительно
нормализует это значение.

### Фора: знак и расчёт

Значение форы хранится **с учётом стороны**:

- Ф1: отрицательное значение, например `-1.5`;
- Ф2: положительное значение, например `+1.5`.

Проверка:

```text
margin = score_p1 - score_p2
Ф1: adjusted = margin + value
Ф2: adjusted = -margin + value
```

Если `adjusted == 0` — возврат/push, результат `success = null` (не считается
ни победой, ни поражением). Если `> 0` — зашла, иначе — не зашла.

### Тотал

Сравнение строгое:

```text
over:  total > threshold
under: total < threshold
```

При равном тотале ставка не засчитывается.

### Обе забьют

```text
yes: score_p1 > 0 and score_p2 > 0
no:  not (score_p1 > 0 and score_p2 > 0)
```

## 6. Встроенный алгоритм по видам

### Настольный теннис

`_analyze_all`: шесть моделей (`streak`, `window`, `markov1`, `markov2`,
`recency`, `base_rate`), фильтры, голосование, прогнозы по партиям
(`set1..set5`), ТБ/ТМ 18.5 и П1/П2. Логика исходного `17allsets.py` сохранена.

### Командные виды и теннис

`_analyze_generic` — прозрачный базовый прогноз:

1. Форма за 5 игр: win rate P1/P2; для футбола/хоккея — draw rate.
2. Очные встречи: win rate, draw rate, средний тотал.
3. Исход:
   - `adj = rate_p1 - rate_p2`;
   - при наличии H2H: `adj = adj * 0.7 + (h2h_rate - 50) * 0.6`;
   - при draw rate ≥ 28% и `|adj| < 12` выбирается ничья (только виды с
     ничьей);
   - при `|adj| >= 8` или ничьей выдаётся прогноз.
4. Тотал:
   - среднее из avg total P1, P2 и H2H;
   - линия из коэффициентов Betcity, иначе из `page_total`, иначе
     `default_total`;
   - если `|average - line| >= margin` — ТБ/ТМ.
5. Уверенность ограничена 0.82 и сравнивается с `min_confidence`.

Это не «чёрный ящик» и не гарантия. Для тонких рынков (фора, ОЗ, нестандартные
тоталы) нужен конструктор.

## 7. Метрики

Количество метрик по видам (на 1.5):

| Вид | Метрики |
|---|---:|
| Настольный теннис | 75 |
| Футбол | 68 |
| Хоккей | 89 |
| Баскетбол | 82 |
| Волейбол | 82 |
| Теннис | 82 |

Правила набора:

- базовый список `METRICS` в `constructor_engine.py`;
- `SET_METRIC_IDS` (метрики партий/сетов) не входят в футбол;
- `DRAW_METRIC_IDS` и `BTTS_METRIC_IDS` не входят в виды без ничьей/ОЗ;
- `GENERIC_EXTRA_IDS` (матчевые тоталы, форы, ОЗ) не входят в настольный
  теннис;
- `SPORT_METRICS` строится при импорте из `SPORT_ORDER`.

Полный список с аргументами и подписями:

```text
docs/ai/generated/metrics/<sport>.json
```

Пересобрать: `python tools/dump_ai_context.py`.

## 9. Хранение правил

`ConstructorEngine(path)`:

- настольный теннис → `path` (обычно `constructor_rules.json`);
- остальные → `<base>_<sport>.json`.

Примеры:

```text
constructor_rules.json
constructor_rules_football.json
constructor_rules_hockey.json
constructor_rules_basketball.json
constructor_rules_volleyball.json
constructor_rules_tennis.json
```

Формат файла:

```json
{
  "version": 2,
  "sport": "football",
  "rules": []
}
```

## 10. Проверка результатов

`ResultChecker`:

- для настольного тенниса проверяет каждую партию отдельно
  (`check_prediction_success`);
- для матчевых рынков вызывает
  `check_match_prediction_success(prediction, parsed, sport)`;
- `parsed` содержит `match` (итоговый счёт) и `total`;
- результат сохраняется в `sent_predictions[*].set_results` и
  `result_checked`.

Тотал для тенниса — сумма геймов; для волейбола/баскетбола — очков; для
футбола/хоккея — голов.

## 11. Особые случаи

- Волейбол: счёт матча — партии, но тотал считается по очкам. Поэтому
  `match_total` для метрик берётся из суммы очков в партиях, а не из `3:1`.
- Теннис: счёт матча — сеты, тотал — геймы. В H2H иногда только одна строка;
  generic и метрики обязаны терпеть короткую историю.
- Футбол: скобка `(2:1)` — только первый тайм, не все периоды.
- Хоккей/баскетбол: в сохранённых страницах может не быть `table.total`;
  линия берётся из коэффициентов, иначе `default_total`.
- Настольный теннис: парсер и модели не менять без регрессий.
