# CHANGELOG

История проекта. Артефакты APK лежат в `..` относительно корня проекта,
исходники промежуточных версий — в `.backups/`.

## 1.18 — 30.10.2026

**Тема:** прибыль на дистанции: EV, ROI, портфель и порог коэффициента.

Главный сдвиг: анализ и авто-правила больше не гонятся за точностью. Правило
считается рабочим, только если оно зарабатывает с учётом коэффициента и
подтверждает это на новых матчах.

Добавлено:

- **денежный слой** `app/src/main/python/profit.py`: EV, ROI/yield, прибыль,
  нижняя граница Уилсона, дробный Келли, максимальная просадка, серия
  поражений, покрытие коэффициентами, проверка out-of-sample и подбор
  минимального коэффициента;
- **коэффициент у каждого наблюдения**: анализатор сохраняет кэф прогноза из
  снимка линии (`odds`), поэтому точность и деньги считаются по одной выборке;
- **денежная сводка анализа** `money`: ROI, EV и EV lower, прибыль, средний
  коэффициент, оборот, просадка, покрытие и рекомендуемая ставка;
- **рабочий портфель** `portfolio`: в ядро попадают только правила с
  положительным EV lower и ROI на достаточной выборке; суммарная экспозиция
  ограничена `PORTFOLIO_BUDGET_PCT = 10%` банка, до `MAX_PORTFOLIO = 8` правил,
  для каждого правила считается дробный Келли и ожидание в единицах ставки;
- **рекомендация «поднять коэффициент»** (`add_odds_floor`): если правило
  убыточно из-за дешёвых ставок, советник предлагает минимальный кэф, при
  котором выборка становится прибыльной; рекомендация привязана к условию,
  закрывается после применения и возвращается, если условие убрать;
- **авто-правила по прибыли**: генерация в value-режиме, проверка низкого
  коэффициента и отрицательного EV lower, отключение убыточных активных
  правил, приоритет прибыльных кандидатов, отчёт с ROI/EV/прибылью;
- **интерфейс**: KPI ROI, EV/EV lower, прибыль и средний кэф на экране
  «Анализ»; карточка «Рабочий портфель» с лимитом экспозиции; денежный эффект
  «до/после» в рекомендациях и проверке правил; подсказка, что высокая
  точность при низком коэффициенте может быть убыточной;
- **веб-кабинет**: коэффициенты, ROI/EV/прибыль/просадка в KPI, по
  устройствам, видам спорта, рынкам, правилам, прогнозам и событиям;
- тест `tests/test_profit.py` (116 проверок) и денежные сценарии в
  `test_auto_rules.py`, `test_recommendations.py`, `test_history_server.py`.

Изменено:

- `analyzer.build_observations` прикрепляет `odds` через
  `profit.odds_for_observation`;
- `analysis_service.build_report` отдаёт `money` и top-level `portfolio`;
- `rule_advisor.py` считает денежные метрики, симулирует правки по ROI/EV,
  строит портфель и поддерживает `add_odds_floor`;
- `auto_rules.py` создаёт и проверяет правила по прибыли, а не только по
  точности; убыточное правило отключается, даже если точность высокая;
- `engine_api._apply_rec_to_rule` применяет `add_odds_floor`;
- SQLite-история хранит `odds` (с миграцией старых баз) и считает
  ROI/EV/прибыль/просадку во всех агрегатах и дневном ряде;
- `tools/prepare_server.py` включает `profit.py` в серверный бандл;
- версия: `APP_VERSION 1.18.0`, `SERVER_VERSION 1.18.0`,
  `versionCode 19`, `versionName 1.18`.

Проверено: офлайн-регрессии (20 наборов), `test_profit.py` (116),
`test_auto_rules.py` (62), `test_recommendations.py` (52),

## 1.14 — 29.10.2026

**Тема:** анализ по нескольким видам, точные рекомендации по правилам и
необязательный онлайн-режим.

Добавлено:

- **выбор видов спорта галочками в «Анализе».** Можно отметить несколько
  видов; пустой выбор означает активный вид. Линия, статистика, прогнозы и

  экран анализа, проверку правил и рекомендации.
- **карточка «Что улучшить в правилах».** Рекомендация называет конкретное

  рекомендации и состояние. При ошибке — локальный расчёт, если включён
  fallback. Токен, таймаут и проверка сертификата настраиваются.
- **WSGI-сервис для alwaysdata.com** без базы данных: `/api/v1/ping`,
  `/api/v1/analyze`, страница состояния, gzip, Bearer-токен. Сборка папки
  для загрузки — `python tools\prepare_server.py`, инструкция —

## 1.13 — 27.10.2026

**Тема:** ИИ по выбранным видам и рынкам, проверка действующих правил,
полноценное обучение нейросети и быстрый запуск на большой истории.

Добавлено:

- **выбор видов и рынков для ИИ.** В настройках ИИ появились чипы видов
  спорта и отдельных типов ставок для каждого вида. Если вид не отмечен,
  облачная модель по нему не вызывается и не тратит лимит. Для
  настольного тенниса доступны только победитель матча и тотал партии.
- **«Добавлять ИИ-прогноз в текущий».** В этом режиме ИИ вызывается только
  при наличии прогноза правил или сети, а его мнение добавляется в то же
  сообщение. Отдельных сообщений только с ИИ нет; при пустом прогнозе
  запрос не тратится.
- **карточка «Проверка активных правил»** в «Анализе». Каждое включённое
  правило проверяется на истории: точность, средняя по рынку, число
  срабатываний, уверенность и условия. Готовые правки — «Ужесточить»,
  «Расширить», «Поправить уверенность», «Отключить» — применяются одной
  кнопкой и сохраняются через конструктор. Проверка работает и при
  выключенной авто-генерации.
- подсказки по каждому виду в карточке нейросети: почему вид не обучается,
  сколько примеров не хватает, сколько ждёт разметки, пауза по плато или
  модель уже обучена.

Исправлено:

- **нейросеть не училась на скрытом слое.** В обратном распространении для
  производной tanh использовалась активация входа вместо активации
  скрытого слоя. Из-за этого нелинейные признаки не осваивались, и точность
  упиралась в базовый уровень. Добавлен регрессионный тест XOR.
- **разметка не запускалась при пустой линии.** Цикл движка выходил раньше,
  чем размечал завершённые матчи. Теперь разметка выполняется до проверки
  «есть ли новые матчи», а ожидание финала увеличено с 36 до 72 часов.
- **ИИ-советник молча терял рекомендации:** в `ai_inspector._collect`
  список событий читался до присваивания, из-за `NameError` сбор советов
  прерывался.
- **повторная пара команд считалась дублем.** Примеры теперь различаются
  по дате матча, поэтому серии и турниры не теряются.

Изменено (скорость):

- история прогнозов сохраняется компактным JSON (без отступов) — файл
  меньше на 30–40%, запуск на большой истории быстрее;
- снимок истории для анализа и экранов больше не делается через полную

## 1.12 — 23.10.2026

**Тема:** честная проверка результатов (нейросеть и ИИ) и обучение,
которое выбирается по отложенной выборке, а не по последней эпохе.

Исправлено:

- **часть прогнозов оставалась непроверенной.** Причины были разные:
  - записи, где было только мнение ИИ (без прогнозов правил и сети),
    пропускались целиком — теперь проверяются;
  - счёт запрашивался отдельным HTTP-запросом на каждый прогноз, часть
    ответов терялась по таймауту — теперь одна линия на весь проход
    проверки (`live_index()`), запрос не чаще раза в 20 секунд;
  - Betcity убирает матч из live-фида сразу после финального счёта, и
    проверка по расписанию его уже не видела — добавлен кэш последнего
    увиденного счёта (`score_cache.json`, TTL 12 ч, до 800 записей).

    «по кэшу», в сообщении — «результат по последнему счёту»;

    в партиях (4 победы), а тотал — по той партии, на которую он дан;
  - стороны матчевых прогнозов «П1/П2/Ничья» не приводились к «P1/P2/X»,
    поэтому «П2» проверялся как «П1» — теперь приводятся; неизвестная
